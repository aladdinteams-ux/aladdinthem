# گزارش آزمون نسخه 3.9.1

## محیط واقعی آزمون
WordPress 6.9.10 (WP-CLI، WP_DEBUG و DEBUG_LOG روشن) روی PHP 8.3.6 و MariaDB 10.11، سرور داخلی PHP، Chromium/Playwright. Elementor **4.4.0 از سورس GitHub** (بدون build؛ بنابراین CSS/JS فرانت‌اند و ویرایشگر آن در دسترس نبود و ۴۰۴ آن‌ها در کنسول طبیعی است) و WooCommerce 10.9.4 (سورس، فقط فرانت‌اند). شبکهٔ سندباکس به wordpress.org دسترسی نداشت.

## نتایج اندازه‌گیری‌شده
| مورد | قبل (3.6.0) | بعد (3.9.1) |
|---|---|---|
| اسکن ۱۵۰ سند ۳۹۰KB — RAM اضافه | ≈ 56 MB | ≈ 1 MB |
| اسکن ۷۵۰ سند (۲۷۹MB داده) | ≈ 56 MB، یک درخواست | ≈ 1 MB، برش‌های قابل ادامه (۲٫۱s کل) |
| `frpme_source()` روی صفحهٔ معمولی ۵۰۰KB | 4.56 ms | 0.17 ms |
در سندهای چندمگابایتی، مصرف قدیمی (۵۰ × اندازهٔ سند) در سایت‌های واقعی می‌تواند از `memory_limit` فراتر رود؛ این حالت اجرا نشد و پیش‌بینی است، نه اندازه‌گیری.

## آزمون‌های اجراشده (پاس)
- اسکن: ادامه پس از قطع (۱۵۰ برش با بودجهٔ زمانی ناچیز)، ادغام با نتایج قبلی، قفل هم‌زمانی و برداشتن قفل کهنه، ثبت خطای دیتابیس و توقف پس از ۵ شکست، زمان‌بندی بدون رویداد تکراری، اجرای کامل Cron (`validation/qa-3.9.1/scan_tests.php`).
- ارتقا 3.6.0 → 3.9.1 روی همان سایت: هش کل وضعیت کاربر (صفحات و متا، تنظیمات `frpme_*`/`frpmt_*`، منو، صفحهٔ اصلی) **قبل و بعد یکسان** بود؛ نوع ویجت قدیمی `frpm-contact` یک صفحهٔ دستی شناسایی شد.
- نصب تمیز از روی دو ZIP روی وردپرس خام: فعال‌سازی، ساخت ۵ صفحه + ۸ الگو + منو + صفحهٔ اصلی در نخستین ورود مدیر، دو بار فراخوانی bootstrap بدون صفحهٔ تکراری، ۲ چرخهٔ غیرفعال/فعال افزونه، تعویض قالب به Twenty Twenty-Five و برگشت، Child Theme، حذف افزونه (فقط وضعیت فنی پاک شد؛ صفحات و تنظیمات ماند)، بدون هیچ Fatal یا خطای FRP در `debug.log`.
- قالب بدون افزونهٔ همراه، افزونه بدون Elementor، افزونه با قالب دیگر: فرانت و پیشخوان بدون Fatal؛ اعلان‌های راهنما نمایش داده شدند.
- امنیت (HTTP واقعی): مشترک/نویسنده به صفحات مدیریتی 403؛ export/import بدون nonce رد؛ مشترک 403؛ import با کلید ناشناخته و حجم >1MB رد؛ import حاوی `<script>` پاک‌سازی شد؛ بک‌اسلش بدون از دست رفتن ذخیره می‌شود؛ CSS سفارشی کاربر بدون `unfiltered_html` پاک نمی‌شود.
- مرورگر (390/820/1440): صفحات home/about/services/contact/blog/article/search بدون `pageerror` و بدون سرریز افقی (یک سرریز textarea نظرات در موبایل پیدا و رفع شد).
- WPCS (فقط قواعد Security/DB/Enqueue): ۰ مورد واقعی؛ هشدارهای باقی‌مانده مثبت کاذب یا خواندن‌های GET بدون عملیات تغییر داده‌اند.

## آنچه آزمون **نشد** (نیاز به محیط/تصمیم)
- ویرایشگر بصری Elementor و ذخیره/ویرایش صفحه در آن (build آن در دسترس نبود)؛ Elementor Pro.
- ووکامرس: فقط بارگذاری فرانت فروشگاه/محصول/سبد/حساب بدون Fatal؛ پیشخوان آن به‌دلیل assetهای build‌نشده خطا داد (مربوط به محیط، نه FRP). خرید/پرداخت آزموده نشد.
- Polylang (سورس بدون build فعال نشد)، WPML، Rank Math، Yoast، LiteSpeed Cache، WP Rocket، Wordfence، Contact Form 7: **نصب/آزمون نشدند**؛ فقط بازبینی ایستا.
- PHP 7.4 و WordPress < 6.9: اجرا نشد (فقط بازبینی نحوی؛ ابزار PHPCompatibility اجرا نشد).
- Lighthouse/Core Web Vitals، آزمون بار واقعی، دستگاه موبایل واقعی.
- ویدئوی پیش‌فرض صفحهٔ اصلی (`/wp-content/uploads/2023/04/InShot_…mp4`) روی سایت نو ۴۰۴ می‌دهد تا ویدئو در تنظیمات انتخاب شود.
